# Workshop

_A data type in the Skills & Practices Framework._

**In one line:** A workshop is a facilitated group session that reaches a shared goal, often ending with a deliverable in hand.

---

## What a workshop is

A workshop is a structured working session where a team comes together, follows a set of steps, and produces something real. The Client Kickoff is a workshop. So is Sprint Retro, and Rapid Ideation. A facilitator guides the group, and the session usually ends with a finished deliverable, a decision, or a stronger team.

Workshops are where a lot of the framework comes to life. They take the abstract pieces, the skills, the practices, the deliverables, and turn them into a couple of hours of real collaboration. For many people, a workshop is the clearest answer to "how do we actually do this together."

The framework carries deep, step-by-step detail for each workshop, so you can run it even if you have never seen it done. Every workshop includes a plain pitch, what you need before you start, the core questions you are answering, the steps in order with time boxes, the sections of the template, and notes on what "done well" looks like and where people trip up.

## Workshops run left to right, not by rigid rule

A workshop's steps are meant to be worked through roughly in order, from the first section to the last. That gives a session a natural flow. But a workshop is still a living session, not a script to obey. Teams adjust, loop back, and spend more time where they need it. The order is a helpful default, not a cage.

## The workshops in this framework

The framework includes a full set of workshops across the whole arc of work, from team-building sessions like Team Ice Breakers and Working Agreements, to discovery and research sessions like Empathy Map and UX Research Analysis, to planning sessions like Sprint Goals and Backlog Management, to strategy sessions like Customer Experience Strategy.

Each workshop lives as its own row with its steps, template sections, and guidance. The full set lives in the **Workshops** table, with its step-by-step detail in the linked Workshop Steps and Workshop Template Sections tables. Treat those as the source of truth, and this document as the map.

## How workshops fit the whole framework

A workshop is where several pieces of the framework meet at once.

- **Deliverables.** Many workshops are built to produce a specific deliverable. A workshop often ends with that deliverable in hand, like the Vision and Scope workshop producing Vision Boards.
- **Activities.** A workshop is a facilitated way to run one or more activities together, with a guide and a goal.
- **Practices.** Workshops are where teams learn and rehearse healthy practices. Some workshops exist mainly to build a practice, like Conflict Resolution strengthening how a team handles disagreement.
- **Duties and stakeholders.** Each workshop is run by a certain duty and brings specific stakeholders into the room, so it is clear who leads and who takes part.
- **Milestones.** Workshops are tied to the milestones where they fit, which is how you know when in a project to run one.

## How to use this data

**If you are about to run one,** open the workshop and read it top to bottom: what to prepare, the core questions, and the steps with their time boxes. You can facilitate a solid session straight from the data.

**If you are learning the craft,** use workshops to see how the pieces combine in real time. Watching a deliverable get built inside a workshop teaches more than reading its definition alone.

**If you are an AI system helping someone,** ground how-to guidance in the workshop's real steps, template sections, and the deliverable it produces. Keep the framing that steps run roughly left to right, and that a team can adapt the session as it goes.

## Where these definitions come from

The workshops are grounded in recognized facilitation and agile practice (for example Scrum's events for the agile sessions), and each is shaped by how Tech Fleet teams actually run it. Tech Fleet's own method is the source of truth where its approach differs from a generic version of a session.
