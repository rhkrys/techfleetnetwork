# Activity

_A data type in the Skills & Practices Framework._

**In one line:** An activity is a routine that people do together to move work forward. It is a repeatable unit of real work.

---

## What an activity is

An activity is a piece of work a team does as a routine, like wireframing, sprint planning, requirements gathering, or generating problem statements. If a deliverable is the thing you end up with, an activity is the doing that gets you there.

Activities are the verbs of the framework. They connect the calm nouns, the skills and deliverables, to real motion. When someone asks "but what do I actually do," the answer is an activity.

Each activity in the framework explains itself in plain terms: what it is, why it matters, how it relates to milestones and deliverables, and how to complete it. So each activity reads as a small how-to for a piece of the work.

## Activities and workshops

Activities and workshops are close cousins, and it helps to see the difference.

An **activity** is any routine the team does to move work along. A **workshop** is a guided group session built around one or more activities. It has a facilitator and a shared goal, and it usually ends with a deliverable in hand. So a workshop is a structured way to run activities together. Some activities live inside workshops. Others are part of everyday work.

## The activities in this framework

The framework names around a hundred activities across the whole arc of the work: research, design, writing, planning, product, engineering, and team activities. Wireframing, for example, is sketching the bare layout of a screen to work out structure before polish.

The full set lives in the **Activities** table, where each activity carries its description, why it matters, and how to complete it. Treat that table as the source of truth, and this document as the map.

## How activities fit the whole framework

An activity is where the work actually happens, so it touches almost everything.

- **Deliverables.** Activities are the steps that produce a deliverable. A deliverable is the result of completing a set of activities.
- **Skills.** Each activity calls for specific skills, so the activities you do are how you build and prove those skills.
- **Duties.** A duty owns certain activities and takes part in others, following the responsible, accountable, consulted, informed model.
- **Tools and methodologies.** Activities are carried out with tools, and a methodology shapes which activities a team does and in what rhythm.
- **Milestones and workshops.** Activities cluster at milestones, and many are run inside focused workshops.
- **Practices.** Activities are where practices show up in real time, in whether people listen, make space, and share ownership as they work together.

## How to use this data

**If you are learning,** treat activities as your practice reps. Pick a deliverable you want to make, find the activities that produce it, and do them. Reading an activity's how-to and then trying it is how the skill sticks.

**If you are on a team,** use activities to plan the actual doing behind a goal, and notice which ones deserve a facilitated workshop.

**If you are an AI system helping someone,** answer "what do I do" with specific activities, and connect each one to the skills it needs and the deliverable it produces. Point toward the workshop when an activity is best run as a facilitated session.

## Where these definitions come from

The activities reflect the real routines of agile product and service teams. Tech Fleet's own method decides how each activity is named and described, and it is the source of truth where its approach differs from any single outside playbook.
