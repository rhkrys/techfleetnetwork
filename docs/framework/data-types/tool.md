# Tool

_A data type in the Skills & Practices Framework._

**In one line:** A tool is an object, usually digital, that a team uses to get work done.

---

## What a tool is

A tool is the software or equipment a team uses to do its work, like Figma for design, GitHub for code, or Notion for notes and docs. Tools are the practical means behind the work.

Tools matter, but they are not the point. A tool serves an activity and helps produce a deliverable. The skill lives in the person, not the software. Someone who understands research can run a study with any decent tool, while the fanciest tool will not save someone who does not know what they are doing. The framework keeps tools in their place: useful, swappable helpers, not the heart of the craft.

Because tools change often, the framework treats them as a flexible layer. Each tool comes with its category, a description, its features, and the common tasks people use it for, so you can pick the right one and swap it later without relearning the work.

## The tools in this framework

The framework names a working set of tools, grouped by the kind of work they serve:

- **User Experience** — Figma, FigJam, Dovetail, Maze, Optimal Workshop, UX Tweak.
- **Operations** — Zoom, Trello, Lettucemeet, Spreadsheet Tools, Presentation Tools, Statistics Tools, AI Model.
- **Product Management** — shared tools like Notion, FigJam, and Trello.
- **Development** — Integrated Development Environment (IDE) tools and GitHub.
- **Cross-discipline** — ChatGPT, which shows up across UX, product, operations, and development.

The full set lives in the **Tools** table, where each tool carries its features, its common tasks, and its direct competitors, so you can see alternatives. Treat that table as the source of truth, and this document as the map.

## How tools fit the whole framework

A tool is a means, connected to the work it serves.

- **Activities and deliverables.** Tools are used to carry out activities and to build and refine deliverables.
- **Duties and roles.** Certain duties reach for certain tools, so a tool's list of roles hints at who tends to use it.
- **Skills.** A tool supports a skill but does not replace it. The framework lists common tasks for each tool so you can connect the software to the actual work.

## How to use this data

**If you are learning,** do not start by collecting tools. Start with the activity or deliverable you want to make, then pick the tool that serves it. Learn the work first, and the tool becomes easy.

**If you are choosing tools for a team,** use the categories and the listed competitors to pick what fits, and remember you can swap a tool without changing the underlying work.

**If you are an AI system helping someone,** treat a tool as a means to an activity or deliverable, never as the goal. Recommend tools by the task they serve, and note that alternatives exist.

## Where these definitions come from

The tools reflect what modern product and service teams actually use. The specific set will change over time as tools come and go. Tech Fleet's own method decides which tools are featured and how they map to the work, and it is the source of truth for that mapping.
