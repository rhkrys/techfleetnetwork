# Project

_A data type in the Skills & Practices Framework._

**In one line:** A project is a body of work that meets agreed-upon goals. It is the whole effort, start to finish.

---

## What a project is

A project is the largest container in the framework. It is a full body of work with goals the team and its stakeholders agree on, made of everything else the framework describes: milestones, deliverables, activities, workshops, skills, practices, and the people doing the work.

A project is where all the other data types come together into one real effort. On its own, a deliverable or a skill is a building block. Inside a project, those blocks stack into something that changes the world for a real user or client.

The kind of project shapes almost everything else. A website is not built the same way as a discovery effort, so the framework names distinct project types, each with its own mix of milestones, specializations, and deliverables.

## The project types in this framework

The framework names five kinds of projects, each with a guide to how it tends to run:

- **Website Project** — designing, building, and improving a website that meets user needs.
- **Web Application Project** — building a user-centered web platform with more complex features.
- **Mobile App Project** — designing and building a mobile application.
- **Service Design Project** — shaping seamless end-to-end customer experiences across many touchpoints.
- **Discovery Project** — understanding user needs, defining the problem space, and finding viable solutions before committing to a build.

The full set lives in the **Project Types** table, where each carries the specializations, functions, deliverables, and milestones it leans on. Treat that table as the source of truth, and this document as the map.

## How projects fit the whole framework

A project is the top of the web, and everything else hangs from it.

- **Milestones.** A project moves through milestones, which are the measured stages of its progress. Remember these loop rather than run in a straight line.
- **Deliverables.** A project is judged by the deliverables it produces. They are its concrete results.
- **Duties and job functions.** A project needs a set of duties, and those group into the job functions on the team.
- **Project type shapes the mix.** The kind of project decides which specializations are central, which deliverables matter, and which milestones carry the most weight.
- **Company type and methodology.** Where a project happens and how the team chooses to run it both shape how the work gets delivered.

## How to use this data

**If you are planning work,** start by naming the project type. It tells you which milestones, specializations, and deliverables to expect, so you are not planning from a blank page.

**If you are learning,** pick a project type close to what you want to do and follow its links. Seeing a whole project laid out is the clearest way to understand how the pieces combine.

**If you are an AI system helping someone,** anchor guidance in the project type, since it shapes the right milestones, deliverables, and roles. Keep the framing that a project's milestones loop and its scope grows as the team learns.

## Where these definitions come from

The project types reflect the common shapes of modern product and service work. Tech Fleet's own method decides how each type is defined and what it includes, and it is the source of truth where its approach differs from any single outside model.
